## ・ Pumpkin (かぼちゃ収穫)
#### pumpkin.py

グリッド上にパンプキンを敷き詰め、**再植えが不要になった行をスキップ**しながら効率的に収穫状態へ持っていくアルゴリズム

## 特徴

### 行単位の最適化
- 一度も植え替えが発生しなかった行を記録  
- 次回以降のループでその行をスキップ  
- 無駄な処理を削減し高速化  

### 植え替え検知ロジック
- 各行ごとに `replant_counts` を計測  
- 1回も植え替えがなかった場合のみ「完成行」と判定  
- `completed_row` に記録して次回以降スキップ  

### 初回ループ
- 初回ループのみ全マスにパンプキンを配置  
- フラグ `first_time` によって制御  

## アルゴリズム概要

処理は以下の流れで行われます。

1. グリッドを初期化（`clear_till()`）  
2. 初回のみ全マスにパンプキンを植える  
3. 各行を走査  
4. 各マスについて：
   - 収穫可能 → スキップ  
   - それ以外 → 再植え  
5. 行内で再植えが0回なら「完成行」として記録  
6. 完成行は次ループ以降スキップ  
7. 全行が完成したら収穫判定　→ 収穫  
8. 以降ループ

## ・ Cactus Sorter（サボテン整列アルゴリズム）
#### cactus_sorter.py

グリッド上にランダムに生成されたサボテンを**隣接スワップのみ**の制約下で整列し、収穫可能状態にするアルゴリズム

本実装では、ゲーム仕様に基づき **局所操作のみで全体を整えるバブルソート系アプローチ** を採用しています。

## 特徴

### 隣接スワップ制約に対応したソート
- 上下左右の隣接マスのみスワップ可能  
- 局所比較を繰り返すことで全体を整列  

### 行・列の2段階ソート
- **行方向ソート（Row Sort）**
  - 左 → 右へバブルソート  
- **列方向ソート（Column Sort）**
  - 下 → 上へバブルソート  

この2ステップを行うことでグリッド全体を整列

### ソート完了の追跡
- `sorted_row`：ソート済み行の記録  
- `sorted_column`：ソート済み列の記録  

すべての行・列が処理されたことを確認してから収穫

### 自動初期化・無限ループ処理
- 毎ループごとに原点 `(0,0)` にリセット  
- 全マスにサボテンを植え直し  
- ソート → 収穫 を繰り返す  

## アルゴリズム概要

処理は以下の流れで行われます。

1. 原点 `(0,0)` に移動  
2. グリッド全体にサボテンを植える  
3. 各行に対してバブルソートを実行  
4. 各列に対してバブルソートを実行  
5. 全行・全列が処理済みか確認  
6. 条件を満たせば `harvest()` を実行  
7. 以降ループ

## ・ Maze Solver (迷路探索)
#### maze_solver.py
`Weird_Substance` で生成される現環境最大サイズのランダム迷路を自動で探索し、  
宝（`Entiteis.Tresure`）を発見・収穫するためのアルゴリズム

迷路はゲーム仕様により **木構造（ループなし）** であり、この特性を活かした高速・軽量 DFS を実装しています。

## 特徴

### 木構造迷路に最適化した DFS 
- 一度探索した枝には二度と進まない  
- 迷路全体を無駄なく探索
- 計算量は O(N²)

### 分岐点に応じたデータ構造
- **2分岐** → `branch2_hist` で座標と親方向だけ保存  
- **3分岐** → `branch3_hist` で座標と未探索の子方向リストを保存  
- **進んだ道** → `move_hist` で座標と子方向と親方向を保存

### 行き止まりでは前回の分岐点まで一気にバックトラック
**move_hist を利用**して分岐点まで最短で戻るため、実行時間が大幅に短縮されます。

### スタート4分岐を検知し、迷路を再生成
スタート地点が  
- 親なし  
- 子方向 4 本
  
になると木構造の前提を満たさなくなるため、迷路をリセットして再生成する設計

## アルゴリズム概要

迷路探索は次の流れで行われます。

1. 現在マスの「親方向」を決定（最初はなし）
2. 親方向を除いて進める方向を数え、  
   - 2本 → `branch2_dict` に記録  
   - 3本 → `branch3_dict` に未探索方角リストを記録  
   - 4本 → スタート4分岐として迷路再生成

3. 未探索の子方向を優先して進む  
4. 行き止まりになったら`move_hist`を利用して分岐点まで一気に戻る
5. 上記を繰り返し、最終的に`measure()`に到達したら、`Entities.Treasure` を収穫して終了

### 補足

本アルゴリズムはゲーム仕様に深く依存しています。  
以下の前提が崩れる場合は動作しない可能性があります。

- 迷路が木構造であること  
- ゴール位置（measure）が迷路生成後に変化しないこと  
- 通路方向が North / East / South / West の4方位であること
